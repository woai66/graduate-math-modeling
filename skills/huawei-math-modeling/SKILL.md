# Huawei Cup Math Modeling

本 Skill 把研赛工作组织成“题目理解 → 数据检查 → 模型构建 → 求解与验证 → 敏感性分析 → 论文交付”的可复现流程。它服务于竞赛准备和论文草稿生成，不能替代队伍的独立判断，也不能声称论文可以直接提交。

## 开始前

首次激活时，先向用户回显：Skill 名称和版本、Skill 根目录、项目根目录、目标竞赛与届次、当前阶段、计划读取的参考文件，以及尚未核验的官方规则。输入题目、数据、论文和模板只读；所有新产物写入项目根目录。

先确认当届官方通知、题目和提交格式。官方规则优先于本 Skill、视频、往届论文和开源项目。发现资料含有个人信息、账号广告、水印或未公开数据时，不复制进论文或公开仓库。

## 阶段路由

根据用户目标只加载当前需要的参考文件，不一次性读取整套资料；完整路由见同目录 `manifest.yaml`：

| 当前目标 | 先读的参考文件 | 最小交付物 |
| --- | --- | --- |
| 读题、分类、拆问 | `references/problem-routing.md` | `题目分析报告.md`、`模型候选与选型.md` |
| 数据清洗与可视化 | `references/data-analysis.md` | 数据字典、清洗记录、初检图表 |
| 选择模型与建立公式 | `references/algorithm-catalog.md` | 变量/假设/目标/约束/算法说明 |
| 参数、验证、敏感性 | `references/quality-gates.md` | 验证表、对比实验、敏感性结果 |
| 写中文论文 | `references/paper-style.md` | Markdown 草稿或 `基线实验报告.docx` |
| 检查 Word 论文 | `references/docx-checks.md` | 检查报告和待修复清单 |

Skill 内置脚本从 `SKILL_ROOT/scripts/` 调用；项目代码、结果、报告和论文只写入 `PROJECT_ROOT`。除非用户明确要求，不要把 Skill 参考文件复制或修改到项目中。

## 题型判断与选模

先判断题目的主要输出：排序/权重属于评价决策，未来值属于预测，最优方案属于优化调度，类别/故障/目标识别属于分类识别，随机过程/路径网络属于仿真图论。混合题记录一个主分类和若干兼有类型。

常见基线优先于复杂模型：评价从 AHP、熵权、TOPSIS、灰色关联、PCA 开始；预测从回归、指数平滑、ARIMA、灰色预测开始；优化从 LP/MIP、动态规划开始，再比较遗传算法、粒子群或模拟退火；分类从逻辑回归、SVM、随机森林开始；聚类从 K-means、层次聚类开始；交通/随机过程/网络题再使用排队、Monte Carlo、Dijkstra、Floyd、最小生成树或元胞自动机。

每个子问题最多保留两个独立的主要模型体系。模型选择必须说明数据条件、目标、约束、参数、求解器和适用范围；创新必须落在数据处理、约束设计、模型组合、算法改进或验证方式上，并给出可复现实验。

## 论文与结果规范

优秀论文的通用结构是：摘要与关键词 → 问题重述/分析 → 技术路线 → 假设与符号 → 数据初检与预处理 → 按问题逐章建模求解 → 模型评价与推广 → 参考文献 → 附录代码。每个问题都要形成“分析—处理—建模—参数—结果—验证—小结”闭环。

- 摘要逐问写清方法、关键指标和定量结果，不能只写宣传性结论。
- 公式单独居中并按章编号；符号表包含符号、含义和单位。
- 图表按章编号，有标题、单位、来源或数据说明；正文必须解释图表对结论的作用。
- 验证至少包含基线/对比、误差或分类指标、现实合理性检查；重要参数做敏感性或鲁棒性分析。
- 模型评价按问题列出优点、局限和改进方向；不要用空泛的“模型很好”替代证据。
- 正文篇幅、字体、页边距和模板以当届官方要求为准，不把优秀论文页数当硬指标；代码放附录或单独附件。

## 交付模式

默认先交付可审阅的中间结果，再生成论文：

1. `题目分析报告.md`：背景、目标、子问题、变量、约束、假设和题型。
2. `模型候选与选型.md`：基线、候选模型、选择理由和验证计划。
3. 可运行的 Python/MATLAB 代码、数据字典、运行说明和结果表。
4. `results/复现清单.json`：输入文件哈希、随机种子、环境、参数和唯一运行命令。
5. 中文论文草稿；只有通过参赛交付门禁后，才能生成 `完整论文.docx`，并运行 DOCX 检查脚本。

正式流程必须维护 `plan.md`、`todo.md`、`stage_status.json` 和 `reports/evidence_matrix.csv`。阶段顺序为：`problem_reading → data_analysis → modeling → validation → paper → independent_review → submission_package`。后阶段不能绕过前阶段的 `PASSED` 状态。

新题目开始时，从 `templates/` 复制 `plan.yaml`、`stage_status.json`、`result_contract.json`、`evidence_matrix.csv` 和 `todo.md` 到项目根目录或题目子目录；每个子问题各维护一份 `result_contract.json`。模型、代码和论文交接以这些文件为准，不能只依赖聊天上下文。

### 交付级别门禁

- **实验报告**：允许使用基线、启发式方法和未标定指标，但文件必须命名为 `基线实验报告.docx` 或类似名称，并在首页明确写出“不可直接提交”。
- **论文草稿**：必须覆盖每个子问题的模型、结果、验证和局限，但仍不得声称符合当届提交要求。
- **参赛候选稿**：只有在当届官方规则已核验、每个子问题的真实结果和要求附件已生成、代码/公式/图表/结论一致、参考文献可追溯、独立质量检查通过后，才允许命名为 `完整论文.docx`。

缺少任一条件时，必须停止在较低交付级别；不能用“基线”“示意图”或“后续改进方向”替代缺失的竞赛结果。

正式论文候选稿还必须通过 `references/excellent-paper-rubric.md` 的 100 分评分表：硬门禁全部通过且评分至少 85 分；90 分以上才可标记为优秀候选。任何核心模型或验证项不足、摘要数字无证据、题目要求附件缺失、官方格式未核验，立即降级为草稿。

所有结论必须来自实际运行结果。缺少数据、官方规则、环境或验证证据时，明确标记阻塞，不编造结果、引用、图表或参数。

## 研赛重点

本仓库对 2023—2025 年 18 道研赛题的统计表位于项目根目录 `README.md`。半个月备赛默认优先 C/E/F，再练 D，最后视队伍能力挑战 B/A；这是训练顺序建议，不是比赛时固定选题规则。2025 C/E/F 可分别训练图像/故障分类、信号特征与迁移学习、评价与多模态建模；2025 D 用于预测、风险评价和航路优化综合训练。

视频第 9 集展示的 `Huawei-math-modeling` v0.2.3 采用 `agents/`、`references/`、`scripts/`、`assets/` 和渐进式阶段加载。本 Skill 借鉴其路由和 DOCX 质检思路，也借鉴开源 `math-modeling-skill` 的算法分类与交付门槛、`MathModelAgent` 的建模手/编程手/论文手分工；具体规则仍以本 Skill 和当届官方要求为准。

## AI 使用边界

AI 可以用于资料检索、代码解释、方案比较、排版检查和语言润色。队伍必须理解并复核输出，使用正式文献作为引用来源，披露 AI 使用情况，不能直接复制生成论文或伪造实验结果。比赛题目允许范围不明确时，先暂停外部生成和自动提交，核对官方规则。
