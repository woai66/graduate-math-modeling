# 阶段合同与门禁

每个阶段有明确输入、输出和通过条件。阶段未通过时，禁止跳到长篇论文写作。

## M1 建模分析

输入：官方题目、附件清单、数据字典。输出：`plan.md`、`todo.md`、`reports/ANALYSIS_MODELING_REPORT.md`、模型候选表。通过条件：每问的目标、变量、约束、假设、数据需求、基线和验证计划完整。

## P1 最小可行结果

输入：M1 通过的模型说明。输出：最小可运行代码、少量结果表和候选图。通过条件：代码可运行，至少一个真实样本得到合理结果，输入输出尺寸/单位正确，异常情况有记录。

## P2 编程终检

输入：完整代码和数据处理记录。输出：全量结果、正式图表、`results/复现清单.json`。通过条件：固定种子或重复运行，代码/公式/图表/数值一致，所有题目要求的附件已生成。

## W1 论文证据大纲

输入：P2 结果。输出：`paper/outline.md`、逐问证据表、图表清单、引用清单。通过条件：每个结论绑定结果文件、图表或文献；不存在没有证据的段落。

## W2 论文终检

输入：完整 Word/LaTeX 论文。输出：`VERIFY_REPORT.md`。通过条件：优秀论文评分表 ≥85 分、红线项全部通过、官方模板和附件要求已核验、渲染后逐页可读。

W2 必须包含两轮独立审阅：技术审阅检查题目覆盖、公式/单位、数据泄漏、验证和数值一致性；论文审阅检查逻辑、图表解释、语言、引用和模板。两轮审阅由未参与对应产物编写的审阅者完成，并记录角色、日期、结论和阻塞项。

## 交付级别

- M1/P1 未通过：只交付分析报告。
- P2 未通过：只交付实验报告或论文草稿。
- W1 未通过：禁止生成长篇正文。
- W2 未通过：禁止命名为 `完整论文.docx` 或声称可以提交。
