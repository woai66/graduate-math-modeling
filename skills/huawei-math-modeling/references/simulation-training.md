# 仿真训练流程

本流程用于在正式比赛前完整演练一套真题。它的目标是训练队伍的决策、交接、验证和论文表达，不是用一套脚本自动生成答案。默认用一个题目做端到端演练，其他题目用于迁移检验。

## 今日启动包

开始前建立一个独立目录，例如 `projects/simulation-training/<year>-<topic>/`，至少包含：

```text
题目卡.md
讨论记录.md
plan.md
todo.md
attachments/           # 原题和格式说明的只读副本或取得说明
code/
data/             # 原始数据说明、哈希和清洗后的中间数据
results/
figures/raw/
figures/final/
reports/
paper/
run_manifest.json
```

大附件不复制进仓库时，`attachments/` 写来源、文件名、大小、SHA-256 和取得命令；不要用个人绝对路径作为唯一入口。

## S0 读题与共同决策（约 60—90 分钟）

1. 读取题面、附件说明和当届规则，列出每问的任务动词、对象、输入、输出、单位、约束和评价口径。
2. 写出至少两个对开放概念的可计算定义；对每个定义给一个反例或极端情形。
3. 提出基线、改进方案和验证方案，注明哪些结论需要用户参与决定。
4. 将已决定事项、未决定事项和本轮实施边界写入 `讨论记录.md`，没有共同决定的核心路线不进入全量实现。

## S1 数据与最小实验（约 90—120 分钟）

完成数据字典、缺失/异常/泄漏检查和一个最小真实样本。先验证字段、单位、坐标/时间顺序和输出格式，再调模型。失败样本、拒识样本和未覆盖对象要单独编号。

## S2 分问建模循环

每一问重复：

`现象与定义 → 数学推导 → 最小代码 → 小样本核验 → 与基线比较 → 失败诊断 → 共同决定是否扩展 → 全量实验`

每轮保存运行命令、参数、输入哈希、结果摘要和下游接口。跨问依赖发生变化时，标记旧结果过期并重算依赖项。

## S3 验证与图表

至少安排一种独立于拟合过程的证据：留出/滚动验证、合成真值、物理约束、穷举小例、人工核验或外部一致性。没有标签时不伪造 Accuracy、IoU、F1 或真实概率。数值图用代码生成；流程图保留 Excalidraw/Archify 可编辑源，并按最终版心导出。

## S4 论文同步写作

先写证据大纲和逐问小结，再写正文。摘要和结论只引用已冻结结果。每个主张都进入 `reports/evidence_matrix.csv`，每张图表有源数据、脚本、版本和正文用途。正文写清选模原因、变量、参数、验证、适用范围和局限。

## S5 复盘与迁移

训练结束时输出：完成时间线、决策变更、返工原因、最耗时步骤、可复用代码、失败样本、论文审阅意见和下一题迁移清单。随后选一题未参与本轮规则调优的题目，只做读题、方案和最小实验，检查流程是否能迁移。

## 仿真训练的停止条件

遇到数据语义、核心概念、题目选择或主模型路线分歧时暂停全量计算，给出证据和选项进行讨论；遇到普通代码报错、排版修复或可逆参数搜索时继续自主处理。训练可在 `research_draft` 或 `reproducible_draft` 停止，前提是明确剩余缺口，不把未完成内容伪装成正式交付。

## 今日最小可行目标

今天不追求写完长篇论文，而是完成一条真实、可复盘的链：题目卡 → 共同选定一个核心定义 → 数据字典 → 一个基线和一个改进小实验 → 一张真实结果图 → 一页证据小结。若时间允许，再扩展第二问；全量运行和 Word 排版放到协议冻结之后。
