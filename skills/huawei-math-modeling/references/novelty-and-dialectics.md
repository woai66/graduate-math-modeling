# 创新与辩证思考规程

本文件规定人和 AI 在建模过程中如何提出新东西、如何自我质疑。它的目的不是让论文显得高深，而是让创新点可被验证、让结论经得起反问。

## 一、要防住的默认倾向

AI 在没有约束时容易滑向四种省力模式，队伍要主动打断：

| 倾向 | 表现 | 打断方式 |
| --- | --- | --- |
| 套模板 | 看到“评价”就 AHP+熵权+TOPSIS，看到“预测”就 LSTM | 先写清现象和要回答的问题，再决定是否需要这些工具 |
| 堆模型 | 用复杂模块撑篇幅，模块之间没有区分度 | 每个模块必须有消融或替代方案，说明去掉它差多少 |
| 顺从 | 用户提出一个想法就顺着往下做 | 先给出最强的反对意见，再给出支持理由，最后才进入实施 |
| 结果先行 | 先跑出一个数字，再倒推一套解释 | 先冻结评价口径和验证协议，再看数字 |

## 二、创新从哪里来

创新不必是发明新算法。以下位置都能产生真实且可辩护的创新：

- **问题的结构**：题面里被忽略的耦合关系、层级关系、时空依赖（例如把“观测设计”引入工程题，让模型输出下一步该测哪里）。
- **数据的特殊性**：缺失机制、量测偏差、设备差异、样本不平衡、坐标系不一致——把数据的“麻烦”变成模型的一部分。
- **约束与边界**：工程上不可行的解、物理上不允许的状态，作为硬约束写进模型。
- **验证方式**：别人只能自证时，你能构造合成真值、物理不变量、穷举小例或跨域留出。
- **定义与命名**：给模糊概念一个可计算定义，并诚实标注它是评分、指数、概率还是物理量。
- **跨领域类比**：把其他领域的成熟思想迁移过来（如最优实验设计、可靠性分析、信息论），但要说明迁移条件。

## 三、创新四问

任何一个“创新点”进入正文前必须回答四问，答不上就降级为候选想法：

1. **新在哪里**：与题目常规做法相比，多做了什么？给出对方做不到的具体情形。
2. **为什么旧方法不够**：是假设不成立、数据不匹配、指标有偏，还是计算不可行？要有证据或反例，不能只说“精度低”。
3. **怎么证明有效**：与谁比较、用什么指标、在什么范围内、失败条件是什么。
4. **边界在哪里**：在什么假设、数据范围、样本规模下成立；超出后会发生什么。

## 四、辩证规程

### 4.1 反方审阅

每一问在冻结方案前，写一段“最强的反对意见及回应”：

- 如果这个模型给出了好结果，最可能是因为什么替代解释（数据泄漏、口径挑选、过拟合、基线太弱）？
- 如果我们错了，最可能错在哪一步？
- 换一个合理口径重算，结论还成立吗？

这段写进过程记录；其中仍然成立的限制，写进论文的模型局限与适用边界。

### 4.2 反例优先

提出一个定义或指标后，先构造反例或极端情形：

- 这个定义在什么输入下会给出明显不合理的值？
- 指标的单调性、对称性、边界行为是否合理？
- 更换量纲或单位后结论是否改变？

反例不能构成反驳时，该定义才进入实现。

### 4.3 竞争性解释

同一个现象往往有多种解释。列出至少两个竞争解释，并设计能区分它们的实验，而不是选一个顺手的解释写进论文。

### 4.4 诚实命名

按证据强度使用名词，越界即视为红线：

| 名词 | 达到它需要的证据 |
| --- | --- |
| 评分 / 指数 | 定义明确、可比、对参数变化不敏感即可 |
| 概率 | 有标定或频率解释；否则只能叫“分数” |
| 准确率 / IoU / F1 | 有独立且可信的标签 |
| 最优 | 满足全部约束且相对已比较的基线最优 |
| 因果 | 有干预或强识别设计；相关性不算 |

## 五、人机分工

- **人负责**：选择题目、确定要刻画的现象、判断哪些假设工程上能接受、决定是否改变核心路线、评估结论是否有实际意义。
- **AI 负责**：穷举候选思路、查找相关工作、推导并核算公式、写代码做小样本核验、设计能区分方案的实验、把结论整理成可审查的文字。
- **共同负责**：对每个创新点完成“创新四问”，对每个模型做一次反方审阅。

讨论要围绕真实分歧展开。AI 每轮应给出可比较的选项、自己的判断以及最关键的待定问题；不能只问“你想用什么模型”，也不能在用户没有决定时默认通过。

## 六、每个子问题的固定动作

1. 用一句话写清本问要回答的现象或决策，并给出至少两个可计算定义。
2. 为每个候选定义准备一个反例或极端情形。
3. 提出至少两条实质不同的模型路线（不是同一模型换参数）。
4. 对首选路线写出最强反对意见。
5. 冻结验证协议，再跑全量实验。
6. 结果出来后，按“创新四问”回填证据；答不上就修改或删除该创新主张。

## 七、禁止的创新表演

- 把常见模型换个名字、加个前缀就称为新模型。
- 只在摘要和结论里声称创新，正文没有对应的推导、对比或消融。
- 用“融合”“优化”“智能”等词代替具体机制。
- 用更长篇幅、更多图表、更多参考文献代替更清楚的论证。
- 用“国奖级”“可提交”等标签代替真实评审与验证。
